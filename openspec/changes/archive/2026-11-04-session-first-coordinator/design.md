# Design

## Decisions

- **Automatic connection:** use public `@opencode/client/service` exports `fallback()` and `headers()`, then `OpenCode.make({fetch})`. Read registration through a bounded, no-follow descriptor; verify ownership, private mode, regular-file/link safety, safe ancestors and stable identity. Require PID equal to `process.pid` and a credential-free, root-path literal-loopback HTTP URL. Reuse the native password transiently without disclosure. Confine transport to that origin, reject redirects and apply cancellation/timeouts. Reject `discover()` because its credentialed probe precedes these guards; never call lifecycle APIs or substitute another service.
- **Instance identity:** register metadata-only identity RPC independently of storage authority. Verify server PID/version and a fresh nonce MAC over origin, location and incarnation using an adapter-local secret. Recheck registration and proof per read batch; unload aborts connections. Identity proves incarnation, not control authority.
- **Shared native reads:** reuse runtime-neutral discovery/status readers across server and TUI. Paginated all-project inventory exposes only identity, title, location, agent and status metadata, explicitly reporting partial/unknown results. Keep native status separate from automation settlement evidence and protected task inspection. Identity failure withholds inventory; storage failure independently blocks mutations. Remove duplicate readers and superseded conversational gates.
- **Manual control:** retain one serialized authority and operation-bound native approval for create/adopt/send. Takeover fences automation. Dispatch requires exactly `{text,scope:string[]}`; declared scope must be a nonempty subset of `binding.scope`. Bind both exact field values and the selected binding/target into approval; revalidate declared scope and immutable binding/target after approval. Reject declared scope exceeding approved scope. Backend checks declarations, not natural-language semantics. Require no extra model judge, observer, receipt, resume or arming; preserve optional automation's observer/reconciliation authority.
- **One ledger:** retain version-1 intents with manual `kind: "manual"`, `generation: 0`, no automation receipt or allowance consumption. Preserve existing records and automatic validation; older readers reject manual records. Durably reserve delivery identity before sending. The shared initial/manual helper admits only acknowledgements matching both `id` and `sessionID`; otherwise retain ambiguity. Unresolved delivery blocks dispatch, survives reload and never triggers resending. Reconcile through shared native delivery reads, not parallel machinery.
